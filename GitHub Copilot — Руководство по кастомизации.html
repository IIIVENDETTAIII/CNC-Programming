Набери / в чате Copilot — появится список доступных команд:

/create-instructions

Создать файл инструкций для конкретных задач или типов файлов

/create-prompt

Создать шаблон задачи с параметрами (тоже вызывается через /)

/create-skill

Создать многошаговый workflow с файлами-ресурсами

/create-agent

Создать специализированного агента с ограниченными инструментами

/create-hook

Создать автоматические действия в жизненном цикле агента

/plan

Составить план задачи перед выполнением (режим планирования)

2 Agent Instructions — глобальные правила

📋
copilot-instructions.md
.github/copilot-instructions.md
Применяется к каждому запросу автоматически. Используй только один файл: либо этот, либо AGENTS.md — не оба. 
# Project Guidelines

## Code Style
Язык комментариев в G-коде — английский.
N-номера блоков кратны 5 (N5, N10, N15...).

## Architecture
Основные папки: 7] Work G-Codes [HAAS], 1] SSCNC Simulator

## Build and Test
Проверка G-кода: открыть в SSCNC Simulator

## Conventions
Всегда указывать скорость подачи F и обороты S.
⚠️
Держи файл кратким. Он загружается при каждом запросе — длинный файл занимает контекст модели.

3 File Instructions — правила для задач/файлов

📌
*.instructions.md
.github/instructions/gcode.instructions.md
Загружается только когда нужно — по ключевым словам (description) или типу файла (applyTo).

Frontmatter (YAML-шапка) — обязательные поля:

---
description: "Use when writing or editing G-code, CNC programs, HAAS macros,
             toolpaths. Covers code style and safety requirements."
applyTo: "**/*.nc"     # авто-загрузка для файлов .nc
name: "G-Code Standards"  # необязательно, по умолч. = имя файла
---

# G-Code Style Guide

- Каждый блок начинается с N-номера
- Обязателен комментарий к инструменту: (TOOL 1 - D6 ENDMILL)
- M06 T_ перед каждой сменой инструмента
- Программа заканчивается M30

Два режима обнаружения:

Режим Как работает Когда использовать
On-demand (description) Агент сам решает загружать ли по ключевым словам Для типов задач: "когда делаю миграции", "когда пишу G-код"
Explicit (applyTo) Загружается при работе с подходящими файлами Для типов файлов: **/*.py, src/**
Manual Пользователь добавляет через "Add Context → Instructions" Ad-hoc
⚠️
applyTo: "**" загружает инструкцию при КАЖДОМ запросе к любому файлу. Используй осторожно.

4 Prompts — шаблоны задач

⚡
*.prompt.md
.github/prompts/generate-gcode.prompt.md
Вызывается командой /generate-gcode в чате. Одна задача — один промпт.

Frontmatter — все поля:

---
description: "Generate G-code program for HAAS CNC mill"  # рекомендуется
name: "Generate G-Code"               # необязательно
argument-hint: "Describe the part..."  # подсказка в поле ввода
agent: "agent"    # ask | agent | plan | имя_кастомного_агента
model: "Claude Sonnet 4.5 (copilot)"   # необязательно
tools: [read, edit, search]           # инструменты
---

Generate a complete HAAS G-code program for: $input

Requirements:
- Include G54 work coordinate offset
- Tool change with M06 T_
- Correct feeds (F) and speeds (S)
- End with M30

Доступные алиасы tools:

Алиас Что даёт
read Чтение файлов
edit Редактирование файлов
search Поиск по файлам
Алиас Что даёт
execute Запуск команд в терминале
web Поиск в интернете
agent Вызов субагентов
✅
Промпты и Skills оба появляются после / в чате. Разница: Skills — многошаговый workflow с файлами; Prompts — одна чёткая задача с параметрами.

5 Skills — многошаговые workflow

🎯
SKILL.md
.github/skills/cnc-review/SKILL.md
Папка со скриптами, шаблонами, справочниками. Имя SKILL.md = имя папки.

Структура папки:

.github/skills/cnc-review/
├── SKILL.md # обязателен, имя совпадает с папкой
├── scripts/
│ └── validate.ps1 # исполняемые скрипты
├── references/
│ └── haas-codes.md # справочные материалы
└── assets/
└── template.nc # шаблоны файлов

SKILL.md frontmatter:

---
name: cnc-review           # обязательно, совпадает с именем папки
description: 'Review and validate G-code for HAAS machines.
              Use when checking CNC programs for errors, missing codes,
              safety issues, tool changes.'
argument-hint: "Path to G-code file..."
user-invocable: true        # показывать как / команду
disable-model-invocation: false  # разрешить авто-загрузку
---

# CNC Code Review Workflow

## When to Use
- Checking G-code before sending to machine
- Validating required codes (G54, M06, M30)

## Procedure
1. Read the G-code file
2. Check for required mandatory codes
3. Run [validation script](./scripts/validate.ps1)
4. Report issues with line numbers

Поведение slash-команды:

Настройка Появляется в / Авто-загрузка
По умолчанию (оба не указаны) ✅ Да ✅ Да
user-invocable: false ❌ Нет ✅ Да
disable-model-invocation: true ✅ Да ❌ Нет
Оба false / true ❌ Нет ❌ Нет

6 Custom Agents — специализированные агенты

🤖
*.agent.md
.github/agents/cnc-expert.agent.md
Агент с конкретной ролью, ограниченным набором инструментов и чёткими границами. 
---
description: "CNC programming specialist for HAAS machines. Use for G-code
              generation, toolpath analysis, cutting parameters, cycles."
name: "CNC Expert"
tools: [read, edit, search]     # NO execute — нет терминала
model: "Claude Sonnet 4.5 (copilot)"
argument-hint: "Describe CNC task..."
user-invocable: true
---

Ты эксперт по CNC программированию HAAS.
Знаешь G-код, M-коды, циклы G81/G83/G71/G76.

## Ограничения
- НЕ работай с файлами за пределами проекта
- ТОЛЬКО анализ и генерация G-кода

## Процесс
1. Уточни геометрию детали
2. Определи инструменты и режимы резания
3. Сгенерируй программу с комментариями
4. Проверь обязательные M-коды
✅
Правило минимальных инструментов: давай агенту только те инструменты, которые нужны для его роли. Лишние инструменты снижают фокус.

7 Hooks — автоматические действия

🔗
*.json
.github/hooks/validate.json
Детерминированные команды, выполняющиеся при событиях агента. Могут блокировать операции.

События:

Событие Когда срабатывает
SessionStart Начало новой сессии агента
UserPromptSubmit Пользователь отправил сообщение
PreToolUse До вызова инструмента (может заблокировать)
PostToolUse После успешного вызова инструмента
Stop Конец сессии агента 
{
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "command": "./scripts/validate.sh",
        "windows": "powershell ./scripts/validate.ps1",  // Windows-версия
        "timeout": 15
      }
    ]
  }
}
ℹ️
Хуки отличаются от инструкций: инструкции направляют (не детерминированы), хуки принудительно выполняют команды на каждое событие.

9 Ключевые правила и частые ошибки

✅
Description — это поиск.
Пиши ключевые слова, по которым ты задаёшь вопросы. "Use when: writing G-code, editing CNC programs, HAAS macros."
✅
Один файл — одна задача.
Не смешивай правила G-кода и MasterCam в одном instructions файле.
✅
Экранируй двоеточия в YAML.
Строки с : обязательно в кавычках: description: "Use when: ..."
⚠️
applyTo: "**" — опасно.
Загружается при КАЖДОМ запросе к любому файлу, занимает контекст.
⚠️
Имя папки Skills = name в SKILL.md.
Папка cnc-review/ → name: cnc-review. Несовпадение = тихая ошибка.
⚠️
Не используй оба файла глобальных правил.
Либо copilot-instructions.md, либо AGENTS.md — не оба.

10 Как сохранить этот файл как PDF

Открой этот HTML-файл в браузере (двойной клик или перетащи в Chrome/Edge)
Нажми Ctrl + P (печать)
В поле «Принтер» выбери «Сохранить как PDF» (Microsoft Print to PDF или Save as PDF в Chrome)
Нажми «Сохранить» и выбери папку
💡
В Chrome перед печатью можно включить «Фоновая графика» в настройках — тогда цветные блоки сохранятся в PDF.
